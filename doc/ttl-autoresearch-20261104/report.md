# TTL 写入与混合读取优化记录

## 选择与结论

应用户要求停止继续优化，选择历史实验 `b6161abbb9cd4878c232c62cb30b7bd4ca5035f1`：这是按已记录的八配置综合分数筛选、并通过老师原始回归验证的较高分候选；并未逐一对所有高分历史候选运行完整回归，因此不能断言它是全部可通过候选中的最高分。其历史综合分数为 1.0959；历史数据用于选择，不代表独立复测结果。

按两阶段事件统计，共有 27 次试验的单轮综合成绩高于所选版本；这 27 次均使用重启间隔 1，内存表上限分别为 6、8 或 10 MiB。未对它们逐一运行完整原始回归，因此不能仅据配置断言全部不可用。

综合分数更高的 `ce3c586d8a5ad220a40f481caa4594bd9582853a`（1.1597）在老师打包的未修改原始回归中有三项失败：`AutoCompactTest.ReadHalf`、`CorruptionTest.NewFileErrorDuringWrite`、`CorruptionTest.TableFileIndexData`。因此未选用。其 168 个课程场景均通过，但不能替代原始回归结果。

选择版本的独立五次复测：`perf_ttl_write` 几何平均 **1.0351**，`perf_ttl_mixed` 几何平均 **1.0972**。它们分别低于原定 1.05、1.10 保底，不能宣称达标或收益收敛。三次重复的完整矩阵分别为 1.0468 和 1.1038，表明结果存在波动。

第一阶段记录了 50 次迭代，以次数上限 `stopped` 归档；第二阶段记录了 20 次迭代。用户随后要求停止迭代，因此没有执行原计划中的 50 次收敛窗口；第二阶段原始状态文件仍记为 foreground active，未伪造 stopped 或 complete 事件。

## 其他性能与正确性

- 官方完整 `combined standard --matrix --repeat 3`：168/168 场景通过；老师原始 C++ 回归 209 通过、2 跳过，C 接口回归与环境回归通过。跳过项依赖未启用的压缩库。
- 项目自身 `leveldb_tests`：304 通过、2 跳过，跳过项同样依赖未启用的压缩库。
- 合入 Project1 后再次运行 `combined standard --matrix --repeat 3`：168/168 场景通过，老师原始 C++ 回归 209 通过、2 跳过，C 接口和环境回归通过。相对原基线的写入家族几何平均 1.0546、混合读取家族 1.1061；独立五次复测仍为 1.0351、1.0972，因此不应据此次三次重复结果宣称保底稳定达成。测试启动后仅修改本报告的表述，数据库代码与所选候选逐字节一致。
- 官方完整矩阵中，`perf_combined_stats_under_write` 的部分 100k 单线程写入项较历史基线明显偏低。对 0% 和 50% 过期配置在同机交替各测 6 次：0% 的 `ttl_put_with_stats_queries` 候选/基线逐对比值范围 0.603–1.762、中位数 0.787；50% 对应中位数 1.087。波动很大，不能排除回退，也不能把单次差异解释为确定幅度；保留原始配对结果供审查。
- 本轮未修改老师官方 benchmark 或其打包原始回归。自适应重启间隔将默认值设为 0（自动），表构造默认使用 16，主数据表首条为 TTL 时使用 1；正值仍为显式间隔。文件布局、内存开销与其他工作负载的权衡应在部署环境复查。

## 记录位置

`results/` 保存原基线、完整矩阵、目标五次重复和配对复测数据；`events/` 保存两个阶段的控制器配置、事件和日志。采样结果涉及工作负载准备和写后校验，按调用栈筛选后用于定位瓶颈，不应直接解释为整轮计时占比。
